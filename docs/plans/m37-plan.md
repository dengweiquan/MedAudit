## 0. 现状结论

后端功能（审计、评估、基线、报告、合规逐条判定、告警、定期复检、模板、操作日志）已经齐全。

## 阶段 1：修正错误（最先做）

### 1.1 复检对比「上次 / 本次」颠倒（Bug，会给出错误结论）

- 原因：`GET /api/v1/bundles` 按 `imported_at DESC` 返回（最新在前），
  `web/src/views/RecheckView.vue` 的 `compare()` 却把 `list[list.length-1]` 当作本次，
  导致「本次」其实是更早的那次，**「已修复」和「新增」整体对调**。
- 改法：`compare()` 里先按 `imported_at` 升序排序再取最后两个；同时检查其他用到
  `bundlesOfAsset` 且依赖顺序的地方（`util.ts`、`DashboardView.vue`、`BundlesView.vue`）。
- 验收：用 `pilot/load-demo.sh` 的演示数据，MySQL 对象「本次」显示导入时间更晚的那个包；
  补一个最小单测或 Playwright 检查，固定「本次时间 > 上次时间」。

### 1.2 事实包列表只返回 100 条

- `internal/platform/import.go` `ListBundles` 有 `LIMIT 100`，对象一多，老对象的最近审计
  会从前端消失（前端用它算每个对象的最新包）。
- 改法：新增按对象取最新包的接口（如 `GET /api/v1/assets/latest-bundles`），前端改用它；
  或去掉 LIMIT 并分页。二选一，优先前者。
- 验收：导入 120 个包后，工作台每个对象的「最近审计」仍正确（加一个 Go 测试）。

## 阶段 2：Web 简洁化（核心）

**设计原则**（每个任务都要遵守）：
1. 一个页面回答一个问题；常见情况下不超过一屏（1366×900 不滚动或只滚一点）。
2. 只用中文业务词：不通过 / 通过 / 证据不足；高 / 中 / 低风险；账号（不说「主体」）。
3. 不显示内部编号；需要时放在「工程师模式」或鼠标悬停提示里。
4. 说明文字最多一行；更多解释放在 `?` 悬停提示。
5. 每个页面只有一个主按钮（蓝色），其余为次按钮。

### 2.1 两种模式：医院模式（默认）/ 工程师模式

- 顶部右侧加开关「工程师模式」，状态存 `localStorage`（读写包 try/catch）。
- **医院模式菜单（5 个）**：首页 · 审计对象 · 问题 · 报告 · 复检对比
- **工程师模式**额外显示：审计记录 · 基线 · 规则 · 关联分析 · 管理
- 这只是界面层的显示切换，**不是权限控制**（现在所有账号同权）；在开关旁悬停提示写明。
- 验收：默认登录看到 5 个菜单；打开开关看到 10 个；刷新后保持。

### 2.2 合并「数据库 / 操作系统 / 中间件 / 业务接口」为「审计对象」一页

- 一张表：对象名称 · 类别 · 上次审计 · 问题（高/中/低 数量）· 操作。
- 顶部类别筛选小标签：全部 / 数据库 / 操作系统 / 中间件 / 业务接口（带数量）。
- 操作只保留：**开始审计**（主）、看问题、导出报告；复检对比放到「更多」或去掉（有专门菜单）。
- 「缺参数」改成文字提示「未配置连接，请工程师在管理页补全」，开始审计按钮置灰并悬停说明。
- 原四个页面的路由保留并跳转到本页对应筛选，避免旧书签失效。
- 验收：4 类对象在一页可见；医院模式下表格不出现资产 ID、事实包 ID、医院 ID。

### 2.3 首页：先告诉用户「现在该做什么」

自上而下只放四块：
1. **一句话结论**（大字）：例「本院 5 个对象，4 个有问题；高风险 38 项待整改。」
   全部清零时：「全部对象检查通过」。
2. **需要你处理**（合并现有「告警」「该复检了」）：一行一件事，带一个按钮
   （看明细 / 去审计 / 已知悉）。没有事项时显示「暂无待办」。
3. **先改这些**：高风险问题按类型取前 5 条（问题名称 · 对象 · 涉及账号数 · 「怎么改」按钮跳问题详情）。
4. **各类对象情况**：保留现有四张类别卡，数字改为「高 x · 中 y · 低 z」。

- 去掉首页「1223 待整改问题（FAIL）」这种总数大字，改为按风险分级。
- 「医院整改进度」表只在多医院时显示（单院部署隐藏）。
- 验收：演示数据下首页一屏内看到结论、待办、前 5 条高风险问题。

### 2.4 问题页：按对象看，不按事实包看

- 顶部改为「对象」下拉（显示名称），默认该对象最新一次审计；事实包选择移到工程师模式。
- 列表按风险分组（高 → 中 → 低），每类问题显示：问题名称 · 涉及账号数 · 风险 · 「怎么改」。
- 去掉规则 ID 行（工程师模式悬停可见）；`high/medium/low` 显示为 高/中/低。
- 展开后沿用 M35 的判定卡（结论 / 原因 / 怎么改 / 基线屏蔽），文案检查一遍全中文。
- 验收：医院模式下问题页不出现英文代码与内部编号。

### 2.5 报告页

- 一张表：对象 · 生成时间 · 问题数（高/中/低）· 合规（不满足 N 条）· 「下载 Word」。
- 每个对象默认只显示最新一份，「历史」折叠展开。
- 验收：一屏内看到所有对象的最新报告并可下载。

### 2.6 复检对比

- 修完 1.1 后：规则 ID 换成问题名称；「仍存在」默认折叠，只展开「已修复」「新增」。
- 顶部一句话：「上次 10-20 → 本次 10-27：修复 6 项，新增 0 项，还剩 46 项。」
- 验收：结论一句话正确（用演示数据核对数字）。

### 2.7 管理页拆成标签（工程师模式）

标签：**审计对象登记** · **用户** · **定期自动复检** · **操作日志** · **本站与系统**
（本站信息、当前查看医院、清场说明）。
- 每个标签只有一件事；登记表单按类别（数据库 / 主机 / 中间件 / 接口）再分一次小标签。
- 验收：每个标签页高度不超过两屏。

### 2.8 全站文案与术语统一

- 新增 `web/src/labels.ts`：结论、风险、类别、状态的中文映射集中在一处，所有页面改用它。
- 全站检索替换：`FAIL→不通过`、`PASS→通过`、`UNKNOWN→证据不足`、`high/medium/low→高/中/低`、
  「主体→账号」（OS 进程类显示「进程」）。
- 灰色长说明压成一行；多余说明改 `?` 悬停。
- 验收：`grep -nE "FAIL|PASS|high|medium|low" web/src/views/*.vue` 只剩代码逻辑中的比较，
  不在模板文字里出现。

### 2.9 Web 验收方式（统一）

- 加 `web/e2e/smoke.spec.ts`（Playwright，仓库已有 Chromium）：起服务 → `load-demo.sh` →
  医院模式逐页截图并断言：菜单 5 个；页面文字不含 `bundle-`、`h-demo`、`db.mysql.` 等内部编号；
  首页含一句话结论。
- 截图存 `web/e2e/__screens__/`（不入库，`.gitignore`），PR 描述附关键页截图。

- 令牌加有效期（缺省 90 天，`ma token -d 天数` 可设，最长 365），过期即拒绝并提示重新生成。
- 可选来源限制：`MEDAUDIT_TOKEN_ALLOW_CIDR`（逗号分隔网段），不在范围内拒绝。
- 迁移 014：`auth_tokens` 加 `expires_at`；老令牌迁移时视为「生成时间 + 90 天」。
- 令牌登录在操作日志备注里已写「令牌登录」，保持。
- 验收：Go 测试覆盖过期、网段外拒绝；`docs/auth.md`、`docs/cli-guide.md` 更新。
