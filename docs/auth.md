# 登录鉴权（M12，服务端 0.12.0-m12 起）

## 机制
- 用户存 auth_users 表（迁移 007；与 001 的署名 users 表无关），口令仅存 bcrypt 哈希。
- 用户表为空时，服务启动自动播种默认管理员：**admin / admin@123**。首次登录后应立即
  在页面顶栏「修改口令」处更改（新口令至少 8 位）；服务端不强制，但交付口径要求改。
- 登录接口 POST /api/v1/auth/login 发放 HttpOnly 会话 Cookie（随机令牌，服务端内存
  会话表，12 小时有效；服务重启后需重新登录）。登录失败限速：同 IP+用户 10 分钟内
  失败 10 次冷却 5 分钟。
- 中间件统一拦截 /api/v1/*：无有效会话返回 401；前端任一请求收到 401 自动回登录页。

## 放行面（明示边界）
- 公开：静态页面（登录页本身）、GET /api/v1/health、POST /api/v1/auth/login。
- /api/v1/agent/download：M9 采集器下载，自有一次性令牌校验，不走会话。
- 机器通道 POST /api/v1/bundles、POST /api/v1/api-audits：目标机采集器回传事实包/
  接口报告的通道，无浏览器会话，保持开放以兼容目标机本地采集回传流程。
  部署含义：内网中能直达服务端口的主机可向这两个接口投递数据（导入有内容校验与
  去重，但不验证投递者身份）。试点现场如需收紧，可在反向代理层为这两个路径单独
  加源地址限制，或保持服务回环绑定 + 堡垒机转发（见部署指南）。
- Cookie 未设 Secure（内网 HTTP 部署）；现场走 HTTPS 反代时建议在反代层终结 TLS。
