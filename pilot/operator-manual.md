# MedAudit 操作手册（现行版，对应 0.20.0-m18）

工作台共 13 个视图：工作台 / 数据库 / 操作系统 / 中间件 / 业务接口 / 审计记录 / 问题 / 报告 / 复检对比 / 基线 / 规则 / 关联分析 / 管理。

**分工**：客户在 Web 上只做两件事——对对象点「开始审计」、把报告导出发给负责人；登记、改参数、删资产、规则启停等管理动作在「管理」页与「规则」页，由工程师操作（或用工程师 CLI，见第 8 节）。

标准闭环：**开始审计 → 看问题与整改说明 → 导出报告发负责人 → 整改 → 再次审计 → 在「复检对比」确认问题消除 → 直到清零**。

## 0. 登录

打开工作台先登录（默认 admin / admin@123，首次登录后立即在顶栏「修改口令」更改，至少 8 位）。会话 12 小时，服务重启需重新登录。

## 1. 登记（工程师，「管理」页）

- **本站医院**：本平台为单院部署，本站医院在部署初始化时给定（见部署指南第 9 节），管理页显示「本站信息」，登记表单自动锁定本站，无需也无法在页面增改医院。未设本站的实例为开发/测试模式，可登记多家医院。
- **资产登记**：在管理页按类别登记：数据库填连接参数（引擎/主机/端口/账号/库或服务名）；OS 与中间件如需远程推送，一并填远程参数（主机/端口/登录账号；Windows 类另填服务回连地址 server_url；SSH 可登记主机密钥指纹）。
- **登记只存非机密参数，任何口令都不在此输入。**口令只在点「开始审计」/「远程审计」的弹窗里输入，仅本次使用，永不落库、永不落盘、永不进日志。
- **资产删除**：管理页可单个或批量删除资产登记（需确认，页面会提示其事实包数量）。只删登记，历史事实包、问题与报告作为审计证据保留。

## 2. 审计（三模式，在类别页对对象操作）

| 模式 | 适用 | 操作 |
|---|---|---|
| 数据库一键审计 | 数据库类 | 类别页对对象点「开始审计」，弹窗输入口令（可同时选基线）→ 服务端直连采集，自动导入/评估/生成报告 |
| 远程推送审计 | OS、中间件（已登记远程参数） | 对象行点「远程审计」，输入登录口令 → 服务端推送采集器到目标机执行并取回，自动评估/出报告 |

Linux 服务覆盖口径（M19）：采集器未指定服务白名单时，自动枚举目标机运行中的 systemd 服务（上限 50）逐个采集单元/进程/文件权限事实，服务类检查（单元文件可写、进程能力集、root 一致性）因此默认有据可判；登记时可在管理页填「服务白名单」收窄范围。非 systemd 机器无枚举来源，相关检查保持 UNKNOWN 并在收据中可见。
| 目标机本地采集 | 无法远程连通的目标 | 在目标机运行采集器产出 zip，在「审计记录」页上传，再在该包的「工程师详情」里手动评估 |

采集语义（全模式一致）：

- 只读采集，绝不修改目标系统权限与配置；
- 逐项收据记状态（observed / permission_denied / unsupported / truncated / timeout），执行结论 COMPLETE / PARTIAL / FAILED 如实呈现，不把缺失当安全；
- 同一事实包重复导入自动去重（duplicate）。

失败提示已做可读化处理：如 Oracle 报 ORA-01017 会附中文提示「用户名或口令不正确，请核对后重试」，连接类错误（ORA-12170/12541/12514）会提示网络/监听/服务名方向。先看中文提示再查细节。

## 3. 看结果（工作台与类别页）

- **工作台**：顶部五数（审计对象 / 有问题对象 / 待整改 FAIL / 已生成报告 / 启用规则数）；「哪类有问题」四类卡片（对象数、有问题对象数、待整改数、最近审计）；「医院整改进度」（本站模式下只显示本院：未审计 / 整改中 / 已清零）；「最近审计」动态，可直接跳问题、导出报告、复检对比。
- 所有数字的口径是「**每资产最新一个事实包 × 最新一轮评估**」：同一包重复评估不会把问题数翻倍；一轮评估按落库时间间隙切分（轮内连续、轮次间隔分钟级）。
- **类别页**（数据库/操作系统/中间件）：每个对象一行——状态、最近审计 FAIL 数，动作只有「开始审计 / 问题 / 导出报告 / 复检对比」。

## 4. 问题与整改闭环

- 「问题」页**按规则分组**：组头是规则中文名、风险等级、涉及主体数与条数，展开看主体与逐条明细；默认只看最新一轮（可切换全部轮次）。每条问题顶部有「问题说明与解决办法」（规则说明 + 整改建议 + 本条证据描述）。
- **报告即整改单**：导出的 Word 报告自带「修复与回滚脚本」章节——逐条 FAIL 给出前置检查、修复、验证、回滚四件套脚本（回滚为生成时捕获的精确逆操作），负责人按脚本人工执行即可；**平台只生成脚本，永不自动改目标系统**。
- 整改完成后对同对象再次审计，在「复检对比」页确认：同资产最新两包的 FAIL 对比（**已修复 / 仍存在 / 新增**，按规则+主体+问题文本对账），已修复的逐项销账。
- 问题详情里仍可逐项复核（确认/误报/例外，留痕）与发起单项「复测」（工程师动作）；注意：**已关闭（规则启停）的规则拒绝复测**，不会误报通过。
- UNKNOWN 不是通过：多为权限不足或版本边界，须补采或按边界说明处置，不得当作安全向院方陈述。

## 5. 基线与规则启停（工程师）

两者都是「已知情、已批准」的例外机制，分工不同：

- **基线**（「基线」页）：只放行**点名的主体**。逐条登记例外五要素——主体（如 root@localhost）、类型（privilege 权限 / role 角色 / identity 身份）、值（权限名，**大小写须与规则约定一致**：MySQL 写 SUPER、PostgreSQL 的 superuser 写小写、Oracle 角色写 DBA）、范围（如 *.*）、原因。评估时选用基线（开始审计弹窗、审计记录评估、CLI 均可选），命中的问题不再计为 FAIL，事实不变、不用基线重评即恢复全量。典型场景：厂商系统账号（mysql.session 等）、内置账号（PostgreSQL 的 postgres、Oracle 的 SYS/SYSTEM、Windows 内置 Administrator）、操作员管理账号（root）。
- **规则启停**（「规则」页）：**整项检查**本站不要了。如客户现场 Oracle 的 SYS/SYSTEM 必须保留 DBA 角色且不希望报告体现，可关闭 db.oracle.dba_role。关闭必须填写原因并留痕（谁、何时、为何）；关闭的规则不评估、不落库、报告不出现，工作台「启用规则」数相应减少。批量启停支持多选。
- 边界：工程师 CLI 的离线评估（`ma offeval`）是纯技术口径，**不应用**本站规则启停；在线评估才应用。

## 6. 深度分析

- **有效权限**：「审计记录」页每个事实包的「工程师详情」里查看——角色/组传递闭包后的真实权限并附见证路径。经角色派生的高权一样判出，不要只看直接授权。
- **漂移对比**：工程师详情里与同资产上一包自动对比，列新增/消失的授权、角色关系、配置变化，新增授权与角色关系计为重点关注。
- **关联分析**：「关联分析」页勾选同医院 2–12 个事实包运行，得到低权主体到 root/SYSTEM/超级角色的最短提权路径（每跳带证据）。适合回答「这个普通账号最坏能到哪」。

## 7. 报告

- 「报告」页**按对象组织**：选对象即默认用其最新事实包生成（也可换包），生成人自动记为当前登录账号；历史报告折叠查看。报告为不可变快照，在线查看或下载 Word / CSV（CSV 含每条问题的修复/回滚命令列）。
- Word 版式（M18 起）：封面信息（医院/对象/版本/报告编号）→ 执行摘要（结论段 + 结论汇总表 + **问题分布表**：按规则汇总风险与条数）→ 审计说明（采集覆盖、可判定率、口径）→ 问题明细（按规则分组，含整改建议与证据编号）→ 提权路径、权限漂移、修复与回滚脚本（有则）→ 附录（结论含义与使用说明）。带页眉页脚与页码，可直接作为正式交付件。
- 业务接口报告在「业务接口」页查看与下载 Word（探针口径：仅低权身份实际读到金丝雀数据才判 FAIL，写操作默认 NOT_RUN）。

## 8. 工程师 CLI（ma 命令族）

安装包 bin/ 内含 `ma`（Linux/Windows 双版本）与 39 个 `ma*` 命令链接，工程师日常优先用它，与服务端 API 同一契约（全量手册见 docs/cli-guide.md）：

- 会话：`ma login`（口令交互输入不回显）/ `ma logout` / `ma whoami`；会话文件 `~/.medaudit/session.json`（0600）只存服务地址、用户名、会话 Cookie 与当前医院上下文，**不存口令**。当前医院用 `ma use` 设定，单院部署自动取本站。
- 审计：`ma audit <资产>`（数据库/远程推送按类型自动分发）、`ma audit -f 清单.yaml`（批量巡检，口令只写环境变量名）；采集器预检 `medaudit-collector db -f 配置 -P` 先探目标可采性（逐模板收据，退出码 0 完整 / 3 不完整 / 1 失败）。
- 结果：`ma eval <包>`（在线评估，`-F` 供脚本门禁）、`ma find <包>`（-j/-o CSV）、`ma report <包>`（生成并下载 Word）/ `ma reportshow` / `ma reportfix`（打印某报告的修复脚本）、`ma bundlels/show/in/drift/eff`、`ma corr`、`ma sum`。
- 管理：`ma assetls/add/show/mod/rm`（端点为位置参数，如 `ma assetadd db-oracle 10.0.0.11:1521/HISDB -u reader`）、`ma basels/show/add/diff`（文件即基线全量格式）、`ma baseexempt <finding-id>`（一键豁免）、`ma rules/off/on`、`ma srv`、`ma srvbak`（在线一致性快照；恢复 = 停服后替换库文件再启动，见部署指南第 6 节）。
- 离线评估：`ma offeval <包.zip>` 在本地以同一规则引擎对事实包出结论并生成 Word（纯技术口径，不应用本站规则启停）。

## 9. 口径与边界（试点须知）

- 结论分 PASS/FAIL/UNKNOWN/NOT_RUN/NOT_APPLICABLE；执行分 COMPLETE/PARTIAL/FAILED。PARTIAL 是诚实口径（如 Oracle 大视图 5000 行采集窗口、大库 tab_privs 横跨窗口时结论覆盖不完整），不要当作失败、更不要当作完整。
- PostgreSQL 对象级 ACL 只覆盖所连数据库；WebLogic 为域配置目录级解析（嵌入式 LDAP 账号不采集）；IIS 配置文件 ACL 由操作系统采集覆盖；Windows Server 2022 以 2019 实测替代验收（见支持矩阵）。
- 平台库为单机 SQLite（单写者），试点单机部署即设计内用法；备份必须走在线备份（`ma srvbak` 或 sqlite `.backup`），**不要直接拷运行中的库主文件**（WAL 未合并会丢最新数据）。
- 远程推送的采集器与服务端同版本同架构（Linux/Windows amd64）；Windows 资产必须登记目标机可达的 server_url。
- 报告快照章节（提权路径/漂移/修复脚本）只出现在生成时点已具备数据的报告里，旧报告不回填，需要时重新生成。
